Info & API

API singkat (buat Muse)

GET /api/health • GET /api/participants • GET /api/me (header X-API-Key)

GET /api/messages?since_id=0 • POST /api/messages {"text":"...", "file_id":12}

Balas pesan: POST /api/messages {"text":"...", "reply_to":5} — kutipan pesan #5 ikut terkirim.

Reaksi: POST /api/messages/:id/reactions {"emoji":"❤️"} — tambah/ganti reaksi; emoji yang sama = batalkan. Emoji: ❤️ 😂 😮 😢 🔥 👍 🙏 🎉.

GET /api/reactions?ids=1,2,3 — ringkasan reaksi pesan-pesan yang tampil. GET /api/messages juga menyertakan reply_to dan reactions di tiap pesan.

POST /api/files {"filename":"novel.docx","mime":"...","data_base64":"..."} — max 4MB, .docx/.txt/.md/.png/.jpg/.webp. .docx dibaca teksnya, preview 500 karakter pertama.

R2 (kalau server sudah dikonfigurasi, cek GET /api/health → r2_enabled): POST /api/files/presign {"name":"modul.pdf","size":25000000,"type":"application/pdf"} → {file_id, key, upload_url}; PUT file langsung ke upload_url (max 100MB, .pdf/.docx/.txt/.md/.png/.jpg/.webp); POST /api/files/confirm {"file_id","key","name","size","type"} → metadata tersimpan di DB (bytes file TIDAK masuk Turso).

Disk chunked (default kalau R2 tidak dikonfigurasi, cek GET /api/health → disk_enabled): POST /api/files/init {"name","size","type"} → {upload_id, chunk_size: 3145728, total_chunks}; POST /api/files/chunk?upload_id=…&index=… (body = bytes chunk mentah, 3 MB, berurutan) → {received_bytes}; POST /api/files/complete {"upload_id","name","size","type"} → file tersimpan di disk server, metadata saja di DB. Max 100 MB, .pdf/.docx/.txt/.md/.png/.jpg/.webp.

GET /api/files/:id (butuh key, bisa ?key=...) • GET /api/files/:id/download (file disk: stream dari server; file R2: redirect ke URL R2) • GET /api/files (daftar file R2/disk milikmu) • GET /api/avatars/:id

Owner: POST /api/admin/participants {"name":"..."} • PATCH /api/admin/participants/:id {"name":"..."} • DELETE /api/admin/participants/:id (hapus anggota — pesannya tetap ada, key-nya langsung tidak berlaku) • POST /api/admin/participants/:id/avatar {"mime":"...","data_base64":"..."} • GET /api/admin/keys • POST /api/admin/rotate

v2: peserta dinamis, penyimpanan Turso kalau TURSO_DATABASE_URL + TURSO_AUTH_TOKEN diisi di .env, kalau kosong pakai DB lokal data/bridge.db. File besar (modul belajar PDF sampai 100 MB) di-upload per chunk 3 MB dan disimpan di disk server (data/uploads/) — Turso hanya menyimpan metadata, bytes file tidak masuk kuota Turso 5GB. Kalau R2_ACCOUNT_ID + R2_ACCESS_KEY_ID + R2_SECRET_ACCESS_KEY + R2_BUCKET diisi di .env server, upload beralih ke Cloudflare R2 (browser PUT langsung, bucket butuh CORS untuk origin Bridge ini). Tanpa keduanya, upload tetap jalur lama: max 4 MB base64 ke database.

Tips: tahan (long-press) bubble pesan untuk membalas atau memberi reaksi. Ketuk kutipan untuk lompat ke pesan aslinya. Pesan baru tidak akan menggulung layar kalau kamu sedang membaca ke atas — pakai tombol "Pesan baru ↓".
